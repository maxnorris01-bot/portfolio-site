# portfolio-site

Personal portfolio for Max Norris. Built with Vite, React, TypeScript and React Router.

## Routes

- `/` — Home: the title and tags, then an animated solar system (`src/components/SolarSystem.tsx`, geometry and timing in `solarmodel.ts`) and a panel. Two planets can be chosen, Background and Site Info; the panel shows that text. The planets stand still while the pointer is over the picture or a planet has keyboard focus, in a hidden tab, and under reduced motion. All the words are in `src/content/home.ts` (the Site Info text is a draft).
- `/resume` — Résumé
- `/satellite-conjunction-screening` — the Satellite Point-of-View Tool (the satellite viewer, with the daily conjunction screening it grew out of). The address keeps its original name so existing links work; the name, intro and tags live in `src/data/satelliteTool.ts`.
- `/shop` — Shop Mode (in the nav): type a product request, watch the job's steps, see a grid of results, rate them (Love / Like / Dislike, with an optional comment), refine and press Shop Again for a new batch, with a Saved panel (loved and liked items from every search) and a usage line. The nav tabs are SatPOV and ShopAI. API client, polling and state in `src/shop/`; the page in `src/pages/Shop.tsx`. In development, `/shop?fixture=empty|running|slow|results|none|error` shows canned states (add `rated`, `again`, `batch2`, `cap`, `saved`, `savedliked`, `savedempty`, `short`, `limit`, `maintenance`) with no network (stripped from the production build).

## Shop Mode proxy

`vercel.json` forwards `/api/shop/*` to the Shop Mode API on Fly with an `x-origin-secret` header taken from the `SHOP_ORIGIN_SECRET` environment variable. See `docs/shop-proxy.md` (how it works, rotating the secret, and what is still unverified until a preview deployment).

## Development

```sh
npm install
npm run dev      # local dev server (also serves api/ functions)
npm run lint     # eslint
npm test         # node:test unit tests in tests/
npm run build    # type-check (app, vite config, api) + production build to dist/
npm run preview  # serve the production build
```

## Structure

- `src/styles/tokens.css` — design tokens (colors, fonts). All colors are referenced through these variables.
- `src/data/satelliteTool.ts` — static facts about the satellite project (repo link, tech stack).
- `api/satellite/summary.ts` — Vercel function, `GET /api/satellite/summary?limit=N` (default 25, max 200; add `&date=YYYY-MM-DD` for a retained day's report). Reads the screening pipeline's full report (`reports/current.json`, ~78 MB) from the public Tigris bucket server-side and returns risk-level counts plus the top-N conjunctions, ranked by risk tier then miss distance (~11 KB at the default limit). Cached by Vercel's CDN for an hour. The satellite page reads from it via `src/hooks/useSatelliteSummary.ts`.
- `src/components/SatelliteGlobe.tsx` + `src/globe/` — the 3D globe on the satellite page, lazy-loaded so three.js and satellite.js (~150 KB gzipped) stay out of the main bundle. It fetches `objects/current.json` (and retained `objects/<date>.json.gz` snapshots for past days, listed in `history/index.json`) straight from the public bucket, whose CORS rule allows the production origin and `localhost:5173`/`4173`. Every object is propagated with SGP4 in its inertial frame, a tenth of the catalog per frame. The Earth mesh is rotated by GMST so the texture lines up with real geography (`tests/globe.test.ts` checks this). Includes near-miss replay from the Show conjunctions list (both objects ringed, with a labelled miss line), point colouring by type, owner or flat with per-category show/hide, curated name filters (constellations and the two historical debris events), ISS/Tiangong station views that follow the station, click-to-inspect any point with its nearest neighbour, a sourced collision-history panel, a time slider (retained days back, ~24 h forward, Live at 1/10/50x), and a Globe | Sky toggle: the Sky view shows every tracked object above a chosen location's horizon on a first-person dome (browser geolocation, or a place looked up with OpenStreetMap Nominatim; the location stays in the browser). Sky geometry lives in `src/globe/sky.ts` and is checked against satellite.js look angles in `tests/sky.test.ts`. The globe is shaded day/night by the Sun's position at the displayed time (`src/globe/sun.ts`, satellite.js's low-precision solar formula, checked against astronomy-engine in tests only), with a soft twilight band and city lights on the night side; a Day/night switch turns it off. Earth textures, 2048×1024 in `public/textures/`: NASA Visible Earth Blue Marble (day) and NASA Earth Observatory Black Marble 2016 city lights (night).
- `src/globe/skydim.ts` — the satellite view dims the sky when it looks at the Earth, as a camera exposed for the sunlit Earth would: the Milky Way glow and the stars are multiplied by factors that depend on how much of the view is Earth (the fraction of a cap of the view's field of view that falls inside the Earth's disc, so narrow and wide fields both behave) and on whether the point below the satellite is sunlit (the shipped defaults, tuned by hand, leave daylight undimmed, 1.0, and take glow and stars to ×0.19 when the Earth fills the view over the night side, blended through twilight), eased over about 400 ms. Only brightness changes (not which stars load, show or can be picked); the Sun, Moon, planets, constellations, the Earth and the selection are never dimmed. Retune from the console with `__globe.skyDim` (`?debug=1` exposes `__globe` on the live site and adds a "sky dim" line to the overlay).
- `src/globe/glowtuning.ts` — the Milky Way glow's look (built from the Gaia glow atlas, `src/globe/glow.ts` and `glowlayer.ts`) and the stars' tuned look, as tuned by hand with the debug panel: glow gain 0.20, saturation 0.60, gamma 1.35 and no blur (with a blur of 0 the background blur work is skipped; the map is the atlas interpolated between pixel centres); stars at brightness ×1.10 and point size ×1.00, with 3.5 magnitudes added to the limiting magnitude at fields wider than 15 degrees (fading to nothing by 5), which shows far more of the 118,217 Hipparcos stars at wide views. The glow gain multiplies the narrow-field and Earth-in-view dimming. Retune from the console with `__globe.glowGain`, `glowSaturation`, `glowGamma`, `glowBlur`, `starBrightness`, `starSize` and `wideLimitOffset` (a changed blur rebuilds the map in the background); `?debug=1` shows the current values.
- `?debug=1` also adds a collapsible **Sky tuning** panel in the Satellite view (`src/components/SkyTuningPanel.tsx`, logic in `src/globe/skytuning.ts`; its own lazy chunks, never fetched without `?debug=1`): sliders for the glow (gain, saturation, gamma, blur), the Earth-in-view dimming (glow and stars, sunlit and night) and the stars (brightness, point size, and a wide-field limiting-magnitude offset that fades out between 15 and 5 degrees), with Reset to defaults, Original look and Copy settings (JSON). The sliders write the same engine settings the console hooks do, and the values are remembered in `localStorage` in debug mode only.
- The satellite tool's page layout (`src/pages/SatelliteTool.tsx` and `.css`, `src/components/SatelliteGlobe.css`, `src/globe/pagelayout.ts`, `src/globe/credits.ts`): a compact header, then the tool (the Globe | Sky | Satellite switch and the Compact button in a row above a full-width map, the clock row attached under it, and a short credits line), then the Conjunction screening, For context and Data and credits sections. The controls for the current mode sit in **one translucent panel over the map's left side** (`clamp(300px, 24vw, 420px)`, its own scrolling, a height that stays inside the map, a soft blur); the engine moves the camera's projection centre into the part of the map the panel leaves free (`PerspectiveCamera.setViewOffset`, `src/globe/viewoffset.ts`: half the panel's measured width, eased over 300 ms, at once under reduced motion, recomputed on resize and when the panel's size changes), so the Earth, the focus and the compass are not behind it; pointer maths (picking, drag, zoom toward the pointer) reads positions from the shifted centre. The compass, the drag hint, the debug overlay and the Sky tuning tab position themselves in the free area through `--free-left`. The map's height is the window less the measured part of the page above it and the clock row (`dvh`, 420px floor, 1500px ceiling); gutters are `--wide-gutter` (`clamp(16px, 2.2vw, 48px)`) and the tool is capped at `--wide-width` (2500px), and on this page the site header uses the same two so the wordmark and nav line up with the content (other pages keep the 1120px header). Under 900px the controls stack above the map instead of over it; on a phone (narrow, or on its side) the panels stay over the map in full screen as before. Compact view (button or the C key, not while typing; remembered for the session) hides the panel. The full credits live in the "Data and credits" section; the map keeps a short line that links to it.
- `src/globe/fovcap.ts` — a **maximum field of view** (default 90 degrees) for the Satellite, Sky and Globe views: the camera's field of view is the vertical angle, so a wide map has a much larger horizontal one (100 vertical on 16:9 is about 130 across, which stretches the edges). The cap limits the larger of the horizontal and vertical angles (portrait phones: the vertical one). It bounds zoom-out, the constellation fit and the starting view; zooming in is unchanged (the imagery and Descend limits win if they ever cross the cap). The Forward preset is tipped down (`forwardPitchDeg` in `pov.ts`) so the Earth's limb stays in the narrower view. Retune from the console with `__globe.maxFov`, or the **Max field of view** slider (45 to 140 degrees) in the `?debug=1` Sky tuning panel, which is included in Copy settings and Reset.
- `src/globe/panelstate.ts` — the overlay panel shows **one state at a time**: *browse* (nothing selected: only the filters, with "Your sky" added in the Sky view, where the location controls have no other home), *object* (a selected satellite, station, conjunction pair or Sky-view body: only its card, with Deselect and View from here), *pov* (the satellite view: only its view and sky controls, with the imagery option last) and *star* (a star, constellation, Sun, Moon or planet selected in the satellite view: only that card, with Deselect). The filters are hidden, not removed, while something is selected, so deselecting brings them back exactly as they were. Phones and the stacked layout follow the same rule. In the satellite view today's imagery (NASA GIBS) is on by default; **Hide today's imagery** switches to the static base map (there is no other base-map selector).
- `src/components/ConjunctionsMenu.tsx` — the **Show conjunctions** button at the far right of the row above the map opens a list (over the map's top right) of the ten closest approaches of the run, closest first, each with both names, the miss distance and the UTC and relative time of closest approach. Choosing a row replays the pair and moves the clock to it. It closes on Escape, an outside click or a choice. The list comes from `closest_approaches` in `GET /api/satellite/summary`, the ten smallest miss distances over every conjunction in the report, whatever their risk tier. The latest run's numbers (objects screened, conjunctions, closest approach, risk breakdown) sit at the top of the page beside the title block.
